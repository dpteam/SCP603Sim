# MEMORY.md — долговременная память проекта

Сжатая выжимка знаний о проекте: что важно помнить, чтобы не наступить на уже собранные грабли.
Читай вместе с `AGENT.md` (правила) и `HISTORY.md` (хронология).

---

## 1. Что это и зачем

Симулятор SCP-603 на .NET 9: безопасная реконструкция объекта. Всё «опасное» — текст, картинки,
счётчики и пометки `[СИМУЛЯЦИЯ]`. Проект служит учебной целью и не должен ни на что реально влиять.

## 2. Инварианты (нарушение = баг)

1. **Детерминизм.** Профиль Морфика версии `v` — функция только от `v`. Исходники версий
   воспроизводимы бит-в-бит при одинаковых настройках. Проверяется тестом
   `e2e: две одинаковые конфигурации дают идентичные исходники`.
2. **Уникальность токенов.** Никакие два токена профиля не должны иметь одинаковое написание —
   иначе лексер станет неоднозначным. Следит `MorphikProfileFactory.Reconcile`.
3. **Round-trip.** Разбор источника и его повторная генерация дают идентичное дерево **в рамках
   одной версии**. Обратная совместимость между версиями отсутствует — и это правильно.
4. **Обфускация не меняет смысл.** Тест сравнивает вывод VM до и после обфускации.
5. **Сцены не трогают мир напрямую.** Только `ISceneEffects` → `Scp603Kernel.ApplyEffect`.
6. **`megaprime` самодостаточен**: magic `MGPR`, версия и дайджест профиля, исходник, байткод.

## 3. Тонкие места (gotchas)

- **Сиды.** Цепочка версий: `seed(v) = 0x5C603 ^ (v * 0x9E3779B97F4A7C15)`. Мощность 16-ричных
  литералов и `unchecked` важна. Не меняй константу 0x5C603 без пересмотра тестов.
- **Парсер `if/else`.** В языках с терминатором-новой-строкой нельзя вызывать `ConsumeTerminator`
  после того, как `SkipNewLines` уже съел строку. Используй флаги `consumedNewline` /
  `terminatorHandled`.
- **Терминатор.** Может быть переводом строки (`NewlineTerminates`) или символом из
  `TokenKind.Term`. Не сравнивай по тексту токена — используй `TokenKind`.
- **Рекурсивные записи.** `MorphikStmt[]` в записях сравниваются по ссылке по умолчанию —
  для сравнения деревьев используй `AstComparer`.
- **`Math.BigMul`** для 64×64 → 128 в тесте простоты; иначе переполнение.
- **`XorShift64.NextInt`** для диапазона использует остаток — это нормально для наших целей,
  но не годится для криптографии.
- **`TextCanvas`**: одна ячейка = один символ; `MeasureText` возвращает `length * CellWidth`.
  Так перенос строк совпадает с реальным выводом (важно для `Wrap`).
- **WPF и `System.IO`.** В WPF-проектах `ImplicitUsings` не включает `System.IO` — добавляй
  `using System.IO;` явно.
- **GUI-данные** лежат в `%LOCALAPPDATA%\SCP603Sim`; CLI — в текущем каталоге (`--base` меняет).
- **Иконка** требуется на этапе сборки (`ApplicationIcon`), поэтому `assets/scp603.ico` должен
  существовать в репозитории.

## 4. Карта модулей (быстрый поиск)

- Простые числа — `Core/Numerics/Primes.cs`.
- ГПСЧ — `Core/Numerics/XorShift64.cs`.
- Диалект языка — `Core/Morphik/MorphikProfile.cs` + `MorphikProfileFactory.cs`.
- Конвейер языка — `Lexer` → `Parser` → `CodeGenerator`; `MorphikObfuscator`, `MorphikCompiler`,
  `MorphikVm`, `MorphikToolchain`, `MegaprimeArtifact`.
- Каноническая программа — `Core/Morphik/ProgramTemplate.cs`.
- Оркестратор — `Core/Kernel/Scp603Kernel.cs` (методы `GeneratePrimes`, `GenerateSources`,
  `CompileFiles`, `ApplyEffect`).
- Сцены — `Core/Scenes/*`, реестр `SceneCatalog`.
- Рисование — `Core/Rendering/ICanvas.cs`, `TextCanvas.cs`.
- Набор сцен версии — `Core/Versioning/SceneSet.cs`.

## 5. Формула окон

Окно запрашивается, когда сгенерированное простое число `p` имеет такой индекс `i` в ряду
простых, что `i` тоже простое. База индекса (`IndexOneBased`) и `StartValue` зависят от версии —
поэтому разные версии «открывают окно на разных числах». Сцена выбирается циклически из
`SceneSet.Sequence` по номеру окна.

