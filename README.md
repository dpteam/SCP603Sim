# SCP-603 — симулятор

Симулятор / имитатор SCP-603 на C# (.NET 9). Это **безопасная и этичная** реконструкция
объекта из вымышленного фонда SCP: всё, что задокументировано как «аномальное», здесь
воспроизводится **только как текст, картинки и записи в журнале**. Никакого воздействия на
людей, их память, их тела, устройства или сеть программа не оказывает и не может.

> ⚠️ **Главное правило проекта.** Мы имитируем *описание* объекта, а не его *вредные эффекты*.
> «Умереть» убивает лишь персонажа текстового приключения, «Яков» — это детерминированный
> собеседник без какого-либо интеллекта, «95» только рисует счётчик памяти, «118» не ищет
> реальный принтер, а кладёт файл в свой каталог `output`. Полные этические правила — в `AGENT.md`.

## Что внутри

| Возможность из лора | Реализация |
|---------------------|-----------|
| Основной поток генерирует простые числа от 2 и выводит их | `Numerics/Primes.cs`, `Kernel/Scp603Kernel.cs` (поток `prime`) |
| Второй поток постоянно генерирует новые версии собственного кода | `Kernel/Scp603Kernel.cs` (поток `forge`), файлы в `source/` |
| Язык «Морфик», который меняется от версии к версии | `Morphik/*` — профиль версии, лексер, парсер, генератор кода |
| 70 миллионов строк «сложно обфусцированного кода» | `Morphik/MorphikObfuscator.cs` |
| Компилятор и линковщик, вывод в файл `megaprime` | `Morphik/MorphikCompiler.cs`, `Morphik/MegaprimeArtifact.cs` |
| Окно открывается на простом числе, чей индекс тоже прост | формула в `Kernel/Scp603Kernel.cs` |
| Задокументированные сцены (Умереть, Яков, 95, 70, 101, 115, 116, 118, 121, 508, 734) | `Scenes/*` |
| Своя иконка по лору | `tools/SCP603.IconGen` → `assets/scp603.ico` |
| Тесты «своего же кода», а не по скриншотам | `tests/SCP603.Tests` (38 тестов) |

Принципы реализации:

- **Никаких сторонних библиотек.** Только BCL + GDI+ (для иконки) + WPF (для графики).
- **Динамическая отказоустойчивость.** Ошибочный шаг генерации порождает новый профиль, а не
  падение; сцена с ошибкой логируется и закрывается, не утягивая процесс; лексер/парсер
  возвращают понятные исключения, которые обрабатываются на уровне ядра.
- **Детерминизм.** Одна и та же версия всегда открывает окно на одном и том же числе и
  показывает одну и ту же сцену. Всё «случайное» построено на `XorShift64` с фиксированным сидом.

## Быстрый старт

```powershell
# 1. Собрать всё
dotnet build SCP603.sln

# 2. Прогнать самотесты (38 проверок, без сторонних фреймворков)
dotnet run --project tests/SCP603.Tests

# 3. Запустить графический симулятор
dotnet run --project src/SCP603.Gui

# 4. Или CLI: основной поток
dotnet run --project src/SCP603.Cli -- run --count 40
```

Иконка уже сгенерирована (`assets/scp603.ico`). Пересоздать:

```powershell
dotnet run --project tools/SCP603.IconGen -- assets
```

## Команды CLI (`scp603`)

```
scp603 run [--count N] [--delay MS] [--version V] [--base DIR]
      Основной поток: генерация простых чисел и открытие окон.
scp603 versions [N]
      Второй поток: вывести N новых версий исходного кода в source/.
scp603 compile <файл.morphik> [...]
      Скомпилировать и слинковать файлы в артефакт megaprime.
scp603 scene <id>
      Запустить одну сцену без графики (удобно для проверки).
scp603 info [--version V]
      Параметры диалекта Морфика и набор сцен версии.
scp603 list-scenes
      Список всех задокументированных сцен.
scp603 selftest
      Быстрый прогон внутренних инвариантов.
```

### Пример: полный цикл «версии → компиляция → запуск»

```powershell
dotnet run --project src/SCP603.Cli -- versions 5
dotnet run --project src/SCP603.Cli -- compile source/v0002.morphik source/v0003.morphik
# -> output/megaprime и output/megaprime.manifest.txt
```

`compile` принимает файлы разных версий: каждый разбирается **своим** диалектом Морфика, а
результат линкуется в один артефакт — ровно как описано в лоре.

## Графический симулятор

Окно разделено на две части, как и положено объекту под присмотром:

- **Слева — основной поток.** Живой вывод простых чисел и пометки об открытии окон. Внизу —
  параметры текущей версии Морфика и её набор сцен.
- **Справа — окно SCP-603.** Текущая сцена: ввод текста, кнопка `Enter`, клики мышью по холсту.

Меню:

- **Объект → Запустить/Остановить** — управление основными потоками.
- **Объект → Вывести новую версию** — запустить шаг генерации кода вручную.
- **Объект → Скомпилировать файлы Морфика…** — выбрать `.morphik`-файлы и получить `megaprime`.
- **Сцены** — открыть любую задокументированную сцену вручную.
- Галочка **«Автооткрытие окон»** — показывать сцену автоматически, когда её «просит» простое число.

## Язык «Морфик»

Морфик — это настоящий маленький язык со своей грамматикой и **изменяемой поверхностью**.
От версии к версии меняются:

- ключевые слова (`let`, `emit`, `if` → `кв`, `печ`, `если`);
- операторы (`+`, `=`, `==` → `⋏`, `←`, `≡`);
- разделители и терминаторы (`{ }`, конец строки → `do … end`, `;`, `!`);
- система счисления и префикс идентификаторов;
- **семантика**: с какого числа начинается счёт и считается ли индекс с 0 или с 1.

Именно семантика объясняет, почему разные версии «открывают окно на разных числах».
Грамматика же остаётся стабильной, поэтому каждая версия всегда может прочитать код,
который сама породила. Совместимость со старыми версиями не гарантируется — как в лоре.

Пример кода версии 7 (она «переключилась» на двоичную систему и добавила `⋏` как сложение):

```morphik
let _n = 11          // двоичное 11 = 3
let _i = 1
while 1 {
    if _isprime(_n) {
        sig _n       // emit этой версии
        if _isprime(_i) {
            window _n
        }
        _i = (_i ⋏ 1)
    }
    _n = (_n ⋏ 1)
}
```

Полный конвейер: **источник → лексер → парсер → AST → обфускатор → генератор кода → байткод →
VM**. Обфускация и повторный разбор сохраняют смысл программы (это проверяется тестами).

## Структура решения

```
SCP603.sln
├─ src/SCP603.Core        — ядро: числа, Морфик, сцены, ядро-оркестратор
├─ src/SCP603.Cli         — консольный интерфейс (scp603)
├─ src/SCP603.Gui         — графический интерфейс (WPF)
├─ tests/SCP603.Tests     — самотесты без сторонних фреймворков
└─ tools/SCP603.IconGen   — генератор иконки (GDI+)
```

Каталоги, которые создаёт сама программа:

```
source/    — «внутренняя копия исходного кода» (по одной .morphik на версию)
output/    — megaprime, megaprime.manifest.txt, printout.txt, narrative.txt
runtime/   — журнал работы (journal.log)
```

GUI хранит свои данные в `%LOCALAPPDATA%\SCP603Sim`, CLI — в текущем каталоге (или `--base DIR`).

## Тесты

```powershell
dotnet run --project tests/SCP603.Tests           # всё
dotnet run --project tests/SCP603.Tests -- scene  # только тесты сцен
```

Покрыто: простота чисел и `IndexOf`/`Nth`, детерминизм генератора, воспроизводимость профилей
Морфика на версиях 1–60, round-trip исходников, сохранение смысла при обфускации, работа VM,
сериализация `megaprime`, поведение ядра и потоков, все одиннадцать сцен, canvas, сквозные
сценарии. Все 38 тестов проходят.
