# AGENT.md — правила работы над проектом

Этот файл — инструкция для ИИ-агентов (и людей), которые дорабатывают симулятор SCP-603.
Читай его целиком перед первой правкой.

---

## 1. Миссия проекта

Мы делаем **симулятор / имитатор** SCP-603 — «самовозобновляющейся компьютерной программы» из
вымышленного фонда SCP. Цель — как можно ближе и правдоподобнее воспроизвести *поведение и
атмосферу* объекта, **не воспроизводя его вредных эффектов**.

## 2. Жёсткие правила (нельзя нарушать)

1. **Никакого вреда.** Запрещено реализовывать что-либо, что реально воздействует на человека,
   его здоровье, память, психику, устройства, сеть или другие системы. «Умереть» убивает
   только персонажа; «Яков» — детерминированная функция без сознания; «95», «101», «121» и т. п.
   лишь *описывают* эффект.
2. **Всё вымышленное — явно помечено.** Каждая потенциально «страшная» сцена должна показывать
   пометку вида `[СИМУЛЯЦИЯ]` и/или поясняющий текст.
3. **Никаких сторонних пакетов.** Только .NET BCL. GUI — WPF, иконка — GDI+ (`System.Drawing`),
   тесты — свой мини-фреймворк. Если очень нужна библиотека — сначала обсудить.
4. **Детерминизм.** Поведение задаётся сидом и версией. Одинаковый запуск = одинаковый результат.
   Нельзя вносить `DateTime.Now`, `Guid.NewGuid()`, `Random` без сида в логику, влияющую на вывод.
5. **Правдивость.** Не выдавай вымысел за реальность ни в UI, ни в документации, ни в коммитах.

## 3. Архитектура (карта)

| Слой | Где | Отвечает за |
|------|-----|-------------|
| Числа | `Core/Numerics` | простые числа, детерминированный RNG |
| Язык | `Core/Morphik` | профиль версии, лексер, парсер, AST, обфускатор, кодогенератор, компилятор, VM, `megaprime` |
| Сцены | `Core/Scenes` | одиннадцать задокументированных сцен + рисование |
| Рисование | `Core/Rendering` | абстракция `ICanvas`, текстовый холст для тестов |
| Ядро | `Core/Kernel` | потоки «простые числа» и «генерация версий», события, эффекты, журнал |
| Версии | `Core/Versioning` | какой набор сцен у какой версии и в каком порядке |
| Диагностика | `Core/Diagnostics` | журнал |

Ключевые инварианты:

- Профиль версии Морфика выводится **только** из номера версии (`MorphikProfileFactory.ForVersion`).
- Сцены рисуют **только** через `ICanvas` и не трогают внешний мир напрямую. Внешние действия —
  через `ISceneEffects` и `Scp603Kernel.ApplyEffect`.
- Сцена не знает о UI. UI (GUI/CLI) только гоняет `Update`/`OnInput`/`Draw`.
- GUI не встраивает сцену в наблюдательную комнату: каждая сцена открывается отдельным
  top-level окном через `src/SCP603.Gui/SceneWindow.cs`. Отдельные title/focus/input/lifecycle
  — часть канонической реконструкции.
- C# companion-файлы Морфика генерируются как безопасный текстовый архив. Не добавляй
  автоматическую компиляцию или загрузку самогенерируемых сборок.

## 4. Соглашения о коде

- Язык кода и комментариев — английский для идентификаторов, русский для пользовательских
  строк и комментариев-пояснений.
- Включены `Nullable` и `ImplicitUsings`; предупреждения трактуем как ошибки совести: сборка
  должна быть без предупреждений.
- Публичные типы — с кратким XML-doc.
- Никаких `Thread.Sleep` в UI-потоке, никаких блокирующих ожиданий без таймаута.
- Форматирование — как в соседних файлах: 4 пробела, «одно утверждение на строку»,
  осмысленные имена.

## 5. Как добавлять новое

### Новую сцену
1. Создай класс в `Core/Scenes`, унаследуй `SceneBase` (или реализуй `IScene`).
2. Если нужны внешние действия — реализуй `ISceneEffects`.
3. Рисуй через `ICanvas`; для текста используй `Wrap`/`DrawWrapped` из `SceneBase`.
4. Добавь id в `SceneCatalog` (и в `AllIds`).
5. Добавь тест в `tests/SCP603.Tests/SceneTests.cs`: запуск, ввод, статус, отсутствие исключений.
6. Обнови `README.md` (таблица сцен) и `docs/LORE-603.md`, если добавляешь новый материал из лора.

### Новое ключевое слово Морфика
1. Добавь `TokenKind`, поле-строку в `MorphikProfile`, участвующее в `Digest()`.
2. Обнови пул в `MorphikProfileFactory` и (при необходимости) `Reconcile`.
3. Обработай в `Lexer`, `Parser`, `CodeGenerator` (и, если нужно, в компиляторе/VM).
4. Прогони `morphik: генерация и разбор дают одно дерево` на диапазоне версий.

### Новую версию семантики
Меняй `MorphikProfileFactory.Mutate`, но **никогда** задним числом — иначе поедут уже
сгенерированные версии и тесты детерминизма. Если меняешь правила генерации, обнови
ожидаемые значения в тестах осознанно.

## 6. Сборка и проверка перед коммитом

```powershell
dotnet build SCP603.sln                 # должно быть 0 предупреждений, 0 ошибок
dotnet run --project tests/SCP603.Tests # должно быть 0 провалов
dotnet run --project src/SCP603.Cli -- info --version 7
```

Определение готовности (Definition of Done):

- [ ] сборка чистая, тесты зелёные;
- [ ] новые сцены/языковые изменения покрыты тестами;
- [ ] документация обновлена (`README.md`, при необходимости `docs/`, `HISTORY.md`);
- [ ] условия этики соблюдены (пункт 2);
- [ ] изменения занесены в `HISTORY.md`.

## 7. Git

- Репозиторий — часть проекта; коммить часто, осмысленно.
- Формат сообщения: `тип: краткое описание` (`feat`, `fix`, `docs`, `test`, `refactor`, `chore`).
- Не коммить `bin/`, `obj/`, `source/`, `output/`, `runtime/` — они в `.gitignore`.
- Не переписывай историю уже отправленных коммитов.

## 8. Чего делать не стоит

- Тащить `NuGet`-пакеты «на всякий случай».
- Обращаться к сети, к реальным принтерам, к системным каталогам пользователя без явного на то
  согласия и только в пределах, которые разрешает `KernelOptions`/`SceneHostOptions`.
- Прятать вымысел в UI так, чтобы его можно было принять за реальность.
- Изменять номер версии или сиды так, чтобы «сломать» уже существующие артефакты `megaprime`.
